# Springfield After Hours Toolkit 0.1.1

**Download one file, open it, and start making a mod. No Node, no npm, no Git,
no command line experience.**

0.1.0 worked, if you already knew how to clone a repository and run npm. That
ruled out most of the people it was for. 0.1.1 changes nothing about what the
tools do and everything about who can reach them.

---

## Downloads

| Your computer                        | File                                   |
| ------------------------------------ | -------------------------------------- |
| **Mac**, Apple Silicon (M1/M2/M3/M4) | `sah-0.1.1-macos-apple-silicon.tar.gz` |
| **Mac**, Intel                       | `sah-0.1.1-macos-intel.tar.gz`         |
| **Windows**                          | `sah-0.1.1-windows-x64.zip`            |
| **Linux**                            | `sah-0.1.1-linux-x64.tar.gz`           |

Not sure which Mac? Apple menu → **About This Mac**.

Each archive contains the `sah` executable, a Start Here file you can
double-click, a beginner README, the licences, and the editor definitions.

**These builds are not code-signed and not notarized.** macOS and Windows will
warn you the first time. The README in the archive explains how to allow the
one file — and why you should not turn Gatekeeper off system-wide.

## New: `sah start`

A guided wizard. It asks for a project name, an author and a folder, explains
every choice, then **shows exactly what it will write before writing anything**.

It never overwrites an existing folder, and there is deliberately no flag to
force it. Someone who mistypes a path should lose nothing.

You get a Mod Launcher mod folder: `Meta.ini`, `CustomFiles.ini`,
`CustomFiles.lua`, a commented example mission, a README explaining what to edit
first, and editor autocomplete already configured.

## New: `sah tools`

The six Pocket Tools as a numbered menu, asking for paths in sentences instead
of flags. You can drag a folder from Finder or Explorer into the terminal.

It calls exactly the same functions the flag-driven commands call — there is no
second implementation. `sah pocket …` is unchanged and remains the scriptable
surface.

## Also new

- `sah definitions install .` — a findable name for the editor setup.
- `sah help` — plain-language help for someone who does not yet know what to
  look for in `--help`.
- Unexpected failures print a short explanation instead of a stack trace.
  `--debug` gives the technical detail.
- [Your first mod project](../getting-started/first-project.md) and
  [Troubleshooting](../getting-started/troubleshooting.md).

## What is tested, and what is not

### Tested

460 automated tests on macOS, Windows and Linux. Each of the four downloads is
**built and smoke-tested on its own native runner** — not cross-built and
assumed. The smoke test proves each binary reports version 0.1.1, works with no
repository around it, and can create a project and then refuse to overwrite it.

Archives are checked for required files, forbidden files, the executable bit
surviving archiving, build-machine paths and credential shapes.

### Not tested

**Nothing in this release has been run in _The Simpsons: Hit & Run_.** No one
who built it has the game, the Mod Launcher, or Windows as a daily driver.

No verified claim is made that a generated project loads, that the example
mission can be completed, or that editor autocomplete passing means a script
works — it does not. Autocomplete checks names and argument counts, nothing
more.

Preparing a mod and testing a mod are different jobs. This toolkit does the
first.

## Signing and notarization

**Not signed. Not notarized.** No Apple Developer certificate and no Windows
code-signing certificate exists for this project, so no such claim is made.

Verify your download instead with the published `SHA256SUMS.txt`:

```sh
sha256sum -c SHA256SUMS.txt
```

---

## Limitations

- Not signed or notarized; your OS will warn you once.
- The Intel Mac build depends on GitHub's `macos-13` runner. If that image is
  retired, that download will be marked unavailable rather than cross-built and
  described as tested.
- Not published to npm and not a VS Code Marketplace extension.
- `Game.lua` is not included — it belongs to Donut Team. Your project needs it
  only to actually run.
- Everything from 0.1.0 still stands: the locations and vehicles registries are
  empty, only the `dummy` objective compiles, and `sah ai` refuses to run.
